# Habitude Obsidian: 무료 습관 기록에서 앱·웹 유입과 구독까지

작성일: 2026-10-23 · 대상: 제품·플러그인·앱·웹·백엔드 담당자

이 문서는 기존 플러그인 코드와 2026-10-15 수익화 정본을 바탕으로 한 제품 명세다. **플러그인은 독립적으로 쓸 수 있는 무료 로컬 제품으로 유지하고, 앱·웹은 기록을 더 넓게 활용하려는 사람이 직접 선택하게 한다.** 유입을 늘리기 위해 기본 기록을 제한하거나 노트를 자동 전송하지 않는다.

정책의 정본은 앱 저장소의 수익화 정책과 검증 계획(`plans/monetization-2026-10-15.md`)이다. 이 문서가 승인된 가격·포함량을 변경하지 않는다. 서비스 출시, 결제 제공자 연결, 실판매, 배포, 클라우드 업로드는 이 문서 작성이나 로컬 플러그인 개선만으로 실행되지 않는다.

## 1. 목표와 설계 원칙

제품 목표는 세 단계다.

1. Obsidian 안에서 습관을 만들고 오늘 기록하고 회고하는 경험을 완성한다.
2. 별도 앱이 필요한 사람이 현재 제공 범위와 준비 중인 기능을 구분해 이해하고 Habitude 웹으로 이동한다.
3. 앱에서 무료 가치를 확인한 사용자에게 실제로 제공 가능한 Sync·Plus 서비스를 설명하고, 웹에서 결제·해지·데이터 반출을 끝까지 처리한다.

사용자의 선택은 각각 독립적이다. 플러그인 설치는 계정 생성 동의가 아니고, 링크 선택은 자료 업로드 동의가 아니며, 구독은 모든 기록의 AI 전송 동의가 아니다. 앱 사용과 플러그인 사용을 서로 강제하지 않는다.

이번 범위의 성공은 검증 가능한 외부 유입 경로, 정직한 기능 상태, 무료 기록의 지속성, 다음 단계의 명확함이다. 클릭 수나 설치 수만으로 유료 수요를 입증했다고 판단하지 않는다.

이번 로컬 개선에서는 `src/companion.ts`의 고정 링크·승인 플랜 카탈로그, 내부 `CompanionModal`, ko/en 안내, checklist·review·coach setup의 작은 소개 카드, `showCompanionPrompts` 영구 숨김 설정, 사용자가 여는 명령·설정 진입점을 구현했다. 모달은 승인된 월·연 가격과 현재 웹사이트의 이전 요금제 노출을 함께 안내하며, 구매를 제공하지 않는다. 소개 표시 변경은 `setCompanionPrompts()`가 카드 영역만 갱신하여 코치 대화·입력 중 초안과 체크리스트 입력을 보존한다.

실제 Obsidian QA에서 발견한 기존 SVG namespace 누락도 수정했다. 날짜·제목 텍스트만 나오던 그래프가 SVG로 처리되도록 `xmlns`를 추가했고, 좁은 체크리스트는 그리드 안에서 가로 스크롤되게 했으며 체크 버튼의 `aria-pressed` 상태를 제공한다. 후속 진행 승인에 따라 로컬 JSON export/import와 웹 소스 정합화, 판매 비활성 서버 코어까지 구현했다. 자동 sync·플러그인 인증·실제 checkout·유료 권한 배포는 완료하지 않았다. 기존 BYOK와 공개 공유는 유지한다. 로컬 구현·QA는 공개 배포나 실판매 완료를 뜻하지 않는다.

## 2. 실제 코드에서 확인한 출발점

아래는 개선 작업 시작 시점의 `0.4.4` 소스 기준이다. 기능 구현과 외부 서비스 운영 확인은 서로 다르다.

|---|---|---|
| `src/store.ts` | `Habits.md`, `Log/YYYY-MM-DD.md`에 습관과 체크 저장. 일정은 매일만 지원 | 파일 소유권이 명확한 것이 핵심 가치. 독립 앱으로 옮기는 호환 계약은 없음 |

| `src/share.ts` | 시간초과·HTTP 오류·잘못된 응답·읽기 실패를 같은 준비 중 알림으로 처리 | 서비스 미출시와 일시적 실패를 구분하지 못함. 업로드 성공·클립보드 실패도 별도 복구 필요 |
| `src/types.ts`, `src/main.ts` | Habitude 계정·구독·권한·동기화 모델 없음. 유입 링크는 고정 홈 URL | 로그인·구매 가능성을 암시하는 UI를 먼저 넣으면 허위 약속이 됨 |

| `README.md` | 네트워크·BYOK·공유 설명 존재 | 외부 Habitude 소개의 성격, 현행 서비스 상태, API 키의 실제 보관 위험을 더 명확히 설명할 필요 |

정확성도 유입보다 먼저다. 새 습관의 주간 분모가 항상 7인지, 미래 날짜·생성 전 날짜가 어떤 의미인지, 60일보다 긴 streak가 어떻게 표시되는지 확인한다. 이를 AI 분석으로 보정하지 않고 결정적인 계산 규칙과 회귀 검증으로 해결한다. 기본 통계의 의미가 틀리면 유료 분석의 신뢰도 세울 수 없다.

## 3. 고객과 가치 제안

고객군은 검증할 가설이며, 현재 사용자 조사 결과로 확정한 세그먼트는 아니다.

| 고객 | 하려는 일 | 플러그인이 주는 가치 | 앱·웹으로 이동할 이유 | 먼저 확인할 질문 |
|---|---|---|---|---|
| Obsidian 중심 기록자 | 노트 옆에서 습관을 기록 | 빠른 체크·Markdown 원본·오프라인 | 노트 작업과 분리된 기록 공간이 필요한 경우 | 무료 플러그인만으로 충분한가? |
| 일기와 습관을 연결하려는 사람 | 행동 기록을 일상 맥락과 함께 회고 | 습관과 기본 통계의 시작점 | 독립 앱에서 글쓰기·타임라인 등 검증된 기능 사용 | 실제로 다시 열어 보는 화면은 무엇인가? |
| 여러 기기 사용자 | 같은 Habitude 기록을 이어서 사용 | Obsidian의 기존 파일 흐름 | 출시 후 Habitude 앱 간 동기화 | Obsidian vault 동기화와 다른 필요가 있는가? |
| AI에 관심 있지만 키 설정이 어려운 사람 | 복잡한 설정 없이 회고 도움 받기 | 선택적인 BYOK·로컬 모델 | 출시 후 Plus의 관리형 AI와 명확한 한도 | 설정 편의·분석 품질 중 무엇에 지불하는가? |

권장 포지셔닝은 “Obsidian에서 시작하고, 원하면 Habitude에서 이어 가는 습관 기록”이다. 앱은 실제로 검증한 기능만 현재형으로 소개한다. 유료 동기화는 ‘Habitude 앱·서비스의 동기화’와 ‘Obsidian 플러그인 연결’을 구분하며, vault 전체 동기화나 Obsidian Sync 대체를 약속하지 않는다.

무료 BYOK는 계속 사용 가능하다. API 요금은 선택 공급자의 조건에 따르며 Habitude Plus 크레딧과 합산하지 않는다. ‘무료 AI’, ‘Plus 구매 시 BYOK 한도 증가’라는 표현을 쓰지 않는다.

## 4. 기능과 요금의 경계

USD 기준. 연 요금은 1년 총 청구액이다. 세금·판매 지역·현지 가격·결제 제공자·환불 조건은 아직 미정이며, 실판매 준비 전 공개 화면에서는 ‘예정 요금제’로 표시한다.

## 5. 전환 여정과 화면 구조

### A. 첫 설치 → 첫 가치

체크리스트를 열면 습관 추가가 주 동작이다. 빈 화면은 “작게 시작할 습관 하나를 추가하세요”와 예시만 보여 준다. 가입 팝업, 결제 권유, 자동 브라우저 열기는 없다. 습관 생성·체크·로컬 회고는 계정 없이 완료된다.

### B. 필요를 느낀 순간 → Habitude 소개

플러그인 내부에 수동으로 열 수 있는 ‘Habitude 알아보기’ 화면을 둔다. 현재 무료 플러그인 기능, 앱에서 검증된 가치, 준비 중 서비스와 예정 가격을 나란히 구분한다. 설명 하단에 “선택하면 브라우저가 열립니다. 노트나 습관 데이터는 전송하지 않습니다”를 표시한다.

체크리스트는 습관이 하나 이상 있을 때 작은 정적 소개 카드 하나를 보여 준다. 주간 회고에서는 체크가 있는 경우에만 보조 카드를 두고, BYOK setup에서는 키 설정을 계속하는 주 동작을 유지한 채 같은 소개로 진입할 수 있다. 이 조건은 화면에 이미 필요한 로컬 데이터만 사용하며 노출·클릭을 기록하지 않는다. 기록 완료·streak 실패·오류 알림을 구매 권유로 바꾸지 않는다.

`showCompanionPrompts`는 기본 true이며, 숨김 선택 뒤 false로 영구 저장한다. checklist·review·coach의 홍보 영역에 일관되게 적용하되, 사용자가 명령·설정으로 소개를 다시 여는 것은 허용한다. 숨긴 뒤 시간 경과·업데이트로 자동 복원하지 않는다. 사용자가 설정에서 다시 켜는 동작도 전체 view를 재생성하지 않고 카드만 갱신하므로 입력 중 초안을 보존한다. 모달의 월간·연간 선택은 예정 가격 비교만 바꾸며 청구를 시작하지 않는다. 외부 동작은 ‘Habitude 웹사이트 방문’으로 명명하고 ‘구독 시작’, ‘지금 업그레이드’, ‘현재 요금제 확인’은 쓰지 않는다.

### C. 웹 도착 → 앱의 무료 가치

웹 도착 페이지 권장 경로는 `/obsidian`이다. 이 경로는 아직 출시 계약이므로 운영 확인 전 고정 홈 링크를 대체하지 않는다. `/app/obsidian`처럼 앱 내부 경로를 선택한다면 공개 landing과 인증 후 앱 목적지를 분리해 계약한다. 앱 설치 가능 OS, 현재 기능, 자료 이전 방법, 미지원 기능, 개인정보 안내, 예정 유료 기능 순서로 설명한다. 스크린샷·데모는 실제 릴리스 기준으로 표시한다.

**2026-10-23 운영 확인에서 출시 차단 항목이 발견됐다.** [현재 웹사이트](https://habitude.ai/en)는 HTTP 200이지만 Free의 최대 10 plans, Premium USD 4.99/월·Unlimited plans와 Fitbit·Apple Watch·IFTTT 관련 안내를 표시한다. 이는 승인된 Free/Sync/Plus와 미출시 상태에 맞지 않는다. 루트의 redirect가 UTM을 보존하는 것과 도착 콘텐츠가 올바른 것은 별개다. 이번 작업은 production 웹사이트를 수정하지 않는다. 웹 담당자가 가격·현재 제공 범위·판매 상태를 정합화하고 검증하기 전에는 이 유입 개선을 공개 배포하지 않는다. 로컬 모달의 예정 가격을 외부 사이트의 현재 판매 가격이라고 표현하지 않는다.

현재 구현된 모달에도 “현재 웹사이트에는 이전 요금제가 표시됩니다. 위 Sync·Plus는 출시 준비 중이며 아직 판매하지 않습니다”라는 경고를 넣었다. 이 안내는 로컬 사용자가 차이를 이해하도록 돕는 조치이며 웹사이트 정합성 gate를 대체하지 않는다.

로컬 앱 사용에 계정을 강제하지 않는다. 앱 미출시·지원 OS 아님·브라우저만 이용 가능할 때는 그 상태를 먼저 표시하고 작동하지 않는 다운로드 버튼을 제공하지 않는다. 출시 알림은 웹에서 별도 선택으로만 제공하며, 이메일 입력과 마케팅 동의를 플러그인 설정에서 받지 않는다.

### D. 무료 앱 사용 → 구체적인 서비스 선택

Sync는 사용자가 실제 동기화를 켜려 할 때, Plus는 제공 중인 AI·심층 분석을 요청할 때 제안한다. 플러그인의 로컬 기록·기본 그래프를 유료벽 뒤로 옮기지 않는다. 플랜 비교에서 ‘기존 로컬 기록은 무료로 계속 사용할 수 있음’을 명시한다. 유료 기능이 준비되기 전에는 대기·알림만 제공하고 선결제를 받지 않는다.

### E. 결제 → 서비스 확인 → 다음 사용

실판매 gate를 통과한 뒤 웹에서 로그인 → 현재 플랜 확인 → 월·연 선택 → 총액·갱신·해지 조건 확인 → 제공자 checkout → 권한 확인 → 실제 기능 실행 순서로 이동한다. 결제 중단은 오류가 아니며 선택한 플랜을 다시 검토하거나 무료 사용으로 돌아갈 수 있다. 결제 성공 리디렉션을 권한의 증거로 삼지 않는다.

## 7. 링크·공시·측정 계약

Obsidian 공식 정책은 클라이언트 텔레메트리를 금지한다. 정적 프로모션은 플러그인 자체 UI 안에 두고 README에 공시한다. 서버 측 측정을 한다면 데이터 처리와 개인정보 정책 링크를 공개한다. 이 문서는 더 좁게, 외부 링크 선택 이후 동의된 웹 측정만 허용한다. [Obsidian 개발자 정책](https://docs.obsidian.md/community-directory/developer-policies)

이번 구현의 URL 계약은 `https://habitude.ai/?utm_source=obsidian&utm_medium=plugin&utm_campaign=companion&utm_content=checklist&intent=explore`다. `utm_content`는 `checklist|coach|review|settings|command`, `intent`는 `explore|plans`의 고정 allowlist다. `plans`는 예정 플랜에 관심을 갖고 이동했다는 출처 맥락이며 구매 세션이나 판매 활성화를 뜻하지 않는다. 미지의 값은 안전한 기본값으로 정규화하거나 거부한다. 사용자별 실험군이나 사용량으로 값을 만들지 않는다.

금지 항목은 기기·설치·vault ID, 사용자 ID, 습관명·개수·streak·완료율, 파일명·경로·노트, 이메일, API 키, auth 토큰, fingerprint, 클라이언트 클릭 이벤트다. 클릭 직전 beacon·analytics SDK·추적 POST를 만들지 않는다. URL의 일반 열기 외에 미리 fetch·prefetch하거나 시작 때 연결하지 않는다. UTM으로 플러그인 클릭 수나 활성 설치 수를 정확히 알 수 있다는 주장은 하지 않는다.

서버에서 수집할 수 있는 것은 공개 페이지 요청의 고정 유입 정보, 사용자가 웹에서 동의한 세션·가입·서비스 사용 이벤트, 결제 처리에 필요한 청구 기록이다. 일반 요청 로그가 남는다는 사실과 보관·삭제를 공시한다. 동의 거절 시 비필수 분석을 수행하지 않는다. UTM은 민감 자료가 아니지만 서버 로그·세션 결합의 개인정보 검토를 생략하는 근거가 되지 않는다.

측정과 고객 검증은 다음처럼 구분한다.

| 질문 | 데이터·분모 | 해석 한계 |
|---|---|---|
| 어떤 위치에서 웹 방문이 오는가? | 고정 `utm_content`별 도착 요청·동의된 웹 세션 | 설치 수·고유 플러그인 사용자·노출 대비 클릭률은 알 수 없음 |

실험은 우선 웹의 문구·플랜 이해도에서 수행한다. 플러그인 사용자를 무작위 추적군으로 배정하지 않는다. 첫 연구는 서로 다른 고객군의 자발적 참여자 5~8명씩을 모집하는 제안이며, 습관 원문·건강정보 수집 없이 과업 완료와 막힌 지점을 기록한다. 출시 gate는 정량 전환율을 임의로 맞추는 대신 참가자가 무료 경계·미출시 상태·청구 주기를 오해하지 않는지 확인하는 것이다. 플러그인 노출 분모·MAU를 측정하지 않으므로 ‘플러그인 사용자 대비 앱 전환율’은 계산할 수 없다. 웹에서 확인 가능한 같은 동의 집단의 단계를 분모로 사용하고 결측·동의 선택 편향을 함께 표시한다.

## 8. 수동 이전을 먼저, 자동 동기화는 별도 출시

### 8.1 현재 안전한 출발점

사용자는 자신의 vault 안 `Habits.md`와 `Log/` 원본을 읽고 복사할 수 있다. 이것을 앱 가져오기나 무손실 백업·복원 완성으로 표현하지 않는다. 이번 내보내기 기능을 넣더라도 ‘로컬 자료 반출’과 ‘앱 호환 가져오기’의 상태를 분리한다.

### 8.2 수동 이전 형식 제안

가져오기 구현 전에 버전이 있는 `habitude-obsidian-export` 계약을 앱과 함께 확정한다. export에는 생성 시각·스키마 버전·플러그인 버전, 습관 ID·제목·생성일·매일 일정·보관 상태, 날짜별 체크 상태와 알려진 제한을 포함한다. BYOK API 키·설정 파일·대화·다른 vault 노트·첨부는 제외한다. 날짜는 `YYYY-MM-DD`의 현지 달력 날짜로 보존하고 UTC 변환으로 하루를 옮기지 않는다.

JSON·Markdown 중 실제 첫 출시 형식은 구현과 importer의 검증 결과로 결정한다. 형식이 호환되지 않는 파일에는 앱 전용이라는 이름을 붙이지 않는다. 빈 데이터, 비정상 줄, 알 수 없는 습관 ID, 중복 ID, 손상된 날짜, 보관된 습관은 조용히 버리지 않고 결과 보고서에 포함한다. 수동 편집된 Markdown 전체가 구조화 필드로 보존되는 것은 아니므로 원본 파일을 별도 보관할 수 있게 한다.

권장 과업 흐름은 **범위 선택 → 로컬 미리보기 → 내보내기 → 앱에서 파일 선택 → 가져오기 미리보기 → 확인 → 결과·실행 취소**다. 내보내기만으로 네트워크 요청을 하지 않는다. 앱의 기본 가져오기도 로컬이며, 뒤의 동기화·AI는 별도 동의를 받는다.

### 8.3 importer 완료 기준

- 기존 플러그인 원본을 삭제·변경하지 않는다. 완료 후 플러그인과 앱은 각각의 자료이며 이후 수정은 자동 반영되지 않는다고 설명한다.
- 습관 수·체크 수·날짜 범위·제외 항목을 실행 전후 비교하고, 실패 시 부분 완료를 성공으로 표시하지 않는다.
- 같은 파일을 두 번 가져와도 중복 생성하지 않는 기준을 둔다. ID·내용 충돌이면 합치기·별도 사본 중 선택하고 기본값을 보수적으로 둔다.
- 이미 앱에 같은 이름의 습관이 있다는 이유만으로 동일 항목으로 합치지 않는다. 제목은 바뀔 수 있다.
- 기록된 false와 기록 부재가 모델에서 다른지 정의한다. 보관 날짜나 일정 이력이 없는 형식을 소급 추정하지 않는다.
- iOS·Android의 파일 선택·다운로드 지원 범위를 검증해 공개한다. desktop 전용 경로 처리로 mobile 호환을 가정하지 않는다.

### 8.4 추후 Obsidian 연결 동기화

Habitude 앱 간 Sync 출시와 Obsidian 플러그인 연결은 별도 gate다. 플러그인 연결의 최초 버전은 전체 vault가 아닌 설정된 Habitude 자료 폴더만 대상으로 한다. 연결·선택·미리보기·업로드 동의와 중지·연결 해제를 제공한다. 다른 Obsidian 동기화 도구와 병행할 경우 두 동기화의 충돌과 중복 여부를 검증한다.

필수 설계 항목은 안정적인 ID, 자료 버전, 삭제 tombstone, 변경 이력·증분, 동일 날짜 동시 체크 변경, 습관명·보관 충돌, 시계 차이, 재시도·중복 제거, 최초 병합·복구 사본이다. 마지막 쓰기 우선 규칙으로 조용히 자료를 잃게 하지 않는다. 읽기 전용 연결이나 일방향 import가 양방향 sync보다 먼저 검증될 수 있다. 결정 전 양방향·실시간·종단간 암호화를 약속하지 않는다.

## 9. 인증·결제·권한의 후속 기술 계약

이 절은 실제 서비스 구현을 위한 요구사항이며, 이번 플러그인이 해당 API를 이미 제공한다는 뜻이 아니다. 결제 제공자는 미정이다. Stripe는 구현 후보를 설명하기 위한 예시로만 사용한다.

### 인증과 연결

1. 유료 서비스가 실제 연결을 필요로 할 때만 사용자가 ‘계정 연결’을 시작한다. 현재 무료 플러그인에는 Habitude 로그인이 필요 없다.
2. 앱·미래 연결 플러그인은 OS의 브라우저에서 인증하고 authorization code + PKCE, 일회용 `state`, 정확한 redirect 검증을 사용한다. 토큰을 일반 유입 URL·UTM이나 return URL에 싣지 않는다. 내장 웹뷰에 계정 암호를 입력받지 않는다. 브라우저·PKCE는 RFC 8252 §6, 요청과 응답의 `state`·redirect 검증은 §8.9–8.10에 근거한다. [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252)
3. 가능하면 플랫폼 보안 저장소를 사용한다. Obsidian의 동기화 가능한 `data.json`에 refresh token을 넣는 것을 기본 해법으로 삼지 않는다. 안전한 모바일 보관·연결 해제가 검증되지 않으면 연결 출시를 미룬다.
4. 연결 해제는 세션을 폐기하고 이후 전송을 중단한다. 로컬 기록 삭제·웹 계정 삭제·구독 해지는 각각 별도 선택이다.

기존 BYOK 키는 vault의 플러그인 데이터에 보관되므로 ‘이 기기에만 안전하게 저장’이라고 보장하지 않는다. `.obsidian`을 동기화·백업하는 환경과 다른 플러그인의 접근 가능성을 안내하고, 내보내기·오류 로그·공유에서 키를 제외한다.

### checkout과 권한 집행

- 웹 세션의 계정과 서버의 billing customer를 연결한다. 플랜·가격·주기는 서버 allowlist에서 고르고 클라이언트가 보낸 금액으로 결제하지 않는다.
- `Free`, `Sync monthly`, `Sync annual`, `Plus monthly`, `Plus annual`을 명시적으로 구분한다. 실제 SKU에는 가격·권한 버전을 기록한다. 과거 premium/월 4.99 placeholder를 재활성화하지 않는다.
- 이미 유효한 구독이 있는 계정은 신규 구매보다 관리·변경 경로로 보낸다. 생성 요청의 idempotency와 진행 중 checkout의 재사용·만료 규칙을 정의한다.
- 제공자 webhook의 서명·재전송·중복·역순 이벤트를 처리하고 서버의 최신 결제 상태를 재확인해 권한을 갱신한다. Stripe를 선택한다면 서명 검증과 중복 이벤트 ID 처리, 이벤트 순서를 보장하지 않는 전달 조건을 공식 지침대로 다룬다. [Stripe webhook 지침](https://docs.stripe.com/webhooks)
- 성공 리디렉션이나 URL 파라미터만으로 권한을 부여하지 않는다. Stripe checkout의 완료·비동기 결제 성공 이벤트와 서버에서 조회한 `payment_status`를 확인하고 같은 세션의 지급을 멱등 처리한다. 성공 페이지에서 상태를 즉시 맞출 때도 동일한 서버 검증·지급 함수를 사용하며 webhook을 대체하지 않는다. [Stripe checkout 지급 지침](https://docs.stripe.com/checkout/fulfillment)
- 후속 `GET /entitlements` 응답은 계정의 tier·상태·효력 시각·갱신 시각, 클라우드 바이트·소스 수·크레딧 잔여량·초기화 시각, 제공 가능한 capability를 반환한다. API 경로는 제안이며 실제 배포 전 버전 계약을 확정한다.
- UI의 잠금 표시만으로 과금을 집행하지 않는다. sync·AI·자동 연동 서버가 요청마다 같은 권한과 quota를 검사한다. 사용량 차감은 작업 ID로 중복 방지하고 예약·확정·실패 환급을 구분한다.
- 권한 응답의 기한·오프라인 표시를 구분한다. 서버 확인 실패를 Free 강등이나 구매 실패로 단정하지 않는다. 로컬 기록은 항상 계속되고, 새 클라우드 작업은 상태 확인까지 보류한다.

## 11. 단계별 작업과 완료 기준

단계는 일정 약속보다 의존성과 출시 gate로 운영한다. P0를 마쳐도 checkout은 열리지 않는다.

### P0 — 무료 제품과 정직한 유입 기반

담당: 플러그인·제품 / 우선순위: 즉시

- 단일 고정 홈 링크를 명시적인 Habitude 소개 경로로 정리한다. ko/en 문구와 미출시 상태, 무료 경계를 표시하고 숨김을 저장한다.
- 원격 광고·클라이언트 분석 없이 고정 UTM만 붙이는 외부 링크 모듈을 둔다. 정상 OS 브라우저 이동과 수동 복구를 검증한다.
- 기존 공개 공유·BYOK의 실제 전송을 숨기지 않는다. README의 서비스·전송·프로모션 공시를 코드와 맞춘다. 공개 공유의 동작 변경은 아래 P1로 분리한다.
- BYOK의 전송 범위·비용과 키 보관을 정확하게 설명한다. 키 없이 checklist를 열 때 외부 요청이 없는지 검사한다.
- 데이터 반출은 실제로 검증한 범위만 제공한다. 앱 importer가 없으면 수동 반출로 명시한다.

완료 기준: 설치·기록·회고·홍보 숨김 뒤 무료 사용이 정상이고, 시작·렌더·숨김 시 네트워크가 0건이며, 외부 이동 URL에 고정 허용 필드 외 자료가 없다. 기존의 명시적 BYOK·공유 요청은 별도 검증한다. 기존 습관·설정 마이그레이션, ko/en 누락, 모바일 폭·키보드·명암, build·lint·관련 회귀 테스트를 통과한다. 카드 숨김·재표시 시 작성 중 입력을 보존하고, 실제 Obsidian에서 SVG 그래프·그리드 내부 스크롤·체크 상태의 접근성을 확인한다. 현행 제공/준비 중이 한 화면에서도 혼동되지 않는다. 이 기준의 로컬 검증은 배포 승인이 아니다. **공개 배포 전 웹의 legacy 가격·미검증 기능 문구를 승인 정책·실제 상태와 맞추는 것이 P0 필수 gate다.**

### P1 — 웹 도착과 무료 앱 이전의 실제 완성

담당: 웹·앱·플러그인 / 선행: P0와 대상 앱 릴리스 검증

- `/obsidian` 도착 페이지·검증된 다운로드·지원 OS·실제 앱 기능·개인정보·지원 경로를 제공한다.
- 버전 있는 export/import 계약과 미리보기·중복 방지·실행 취소를 구현한다. 원본 Markdown 보존 범위를 문서화한다.
- 기존 공개 공유는 서비스 운영·보관·삭제를 확인한 뒤 미리보기·제목 숨김/가명화·전송 확인을 추가하고 실패 원인을 구분한다. 미출시라면 요청 전 차단하고 로컬 반출 대안을 제공한다. 공유를 앱 유입의 필수 단계로 만들지 않는다.
- 자발적 참여자로 ‘첫 습관 → 웹 → 앱 설치 → 파일 선택 → 결과 확인’을 관찰한다. 플러그인 추적은 추가하지 않는다.

완료 기준: 대표 정상·빈·큰·손상·수동 편집·보관·중복 데이터에서 습관 수·체크 수·날짜가 일치하거나 손실을 사전 공개한다. 지원 OS의 실제 설치와 offline 무료 사용을 검증한다. 웹에서 앱 출시와 미출시 유료 기능이 명확하다. 동의 거절 뒤 비필수 웹 측정이 중지된다.

### P2 — 서비스와 권한을 test 환경에서 검증

담당: 백엔드·앱·보안·제품 / 선행: 유료 가치·운영 정책 결정

- 선택한 결제 제공자의 test mode에 4개 유료 SKU와 server entitlement를 구현한다.
- 실제 제공할 sync·자동 소스·AI 작업과 quota를 연결한다. AI 상세 가중치·월 경계·실패 환급을 결정한다.
- 결제 완료·비동기 결제·실패·중단·webhook 중복·역순·분실·재처리, 중복 구매, upgrade/downgrade, 취소·만료·환불을 통합 검증한다.
- 저장·소스·크레딧 초과, offline·auth 만료, 클라우드 반출·삭제·복구를 검증하고 지원 절차를 만든다.

완료 기준: 결제 서버·권한 서버·제품 화면의 플랜과 기간이 같은 결과를 보여 주고, 중복 이벤트가 권한·차감·청구를 중복시키지 않는다. 새 유료 작업은 실제 권한으로 집행되고 무료 원문 접근은 보존된다. 운영자가 상태 불일치를 재현·복구할 수 있다. 실제 돈은 청구하지 않는다.

### P3 — 제한된 실판매

담당: 제품 책임자·운영·결제 담당 / 선행: 서비스 준비·운영·별도 판매 실행 승인

- 판매 국가·세금·결제 제공자·환불·지원·개인정보·해지 후 보관 기간을 확정·공개한다.
- 준비된 기능만 판매하고 소수 유료 고객의 권한·지원·원가를 확인한다. 전체 플러그인에 구매 버튼을 일괄 노출하는 일은 서비스 검증 후 진행한다.
- 결제·권한 장애 시 신규 판매만 중단하는 운영 kill switch를 서버에 둔다. 플러그인은 원격 판매 코드를 받아 실행하지 않는다.

완료 기준: 청구·기능 사용·해지·반출·환불 전체 흐름의 실제 운영 증거가 있고, 지원 응답 책임자와 장애 복구 경로가 정해져 있다. 가중 크레딧·저장·전송·소스 비용과 수수료를 반영한 기여 이익을 검토한다. 계정 수·구매 의향·매출을 구분해 보고한다.

### P4 — Obsidian 연결·고급 분석 확장

담당: 플러그인·앱·백엔드 / 선행: P3의 신뢰성과 해당 요구 검증

명시적 연결, 부분 범위 동기화, 병합·복구, 외부 소스 확대, 심층 분석은 각각 독립 출시한다. 자동 동기화 동의 없이 기존 무료 사용자 자료를 업로드하거나, 새 버전에서 기존 BYOK를 Plus로 전환하지 않는다. 데이터 충돌·중지·연결 해제·유료 만료 이후 재연결을 검증해야 완료다.

## 14. 저장소 간 소유권과 계약 검증

이 저장소는 웹·앱·결제 서버의 운영 상태를 통제하지 않는다. 문구만 서로 복사하면 가격과 기능이 다시 어긋날 수 있으므로 아래 역할을 정한다. 특정 담당자 이름은 아직 미정이다.

| 계약 | 소유 역할 | 소비 역할 | 변경·검증 방식 |
|---|---|---|---|
| 가격·포함량·무료 경계·판매 상태 | 제품 책임자 | 모든 저장소 | 수익화 정본·버전 있는 catalog fixture. 변경 승인 이력 보존 |
| 공개 URL·언어 redirect·UTM 보존 | 웹 담당자 | 플러그인·앱 | 공개 경로 목록과 `lastVerifiedAt`·검증 결과 기록 |
| 로컬 export/import 스키마 | 플러그인·앱 공동 | 양쪽 구현 | 버전·호환 fixture·지원 범위·실패 보고를 함께 검증 |
| entitlement·quota·효력일 | 서비스 백엔드 담당자 | 앱·향후 연결 플러그인 | API schema·계약 테스트. 실제 enforcement는 서버 |
| 결제 SKU·청구·환불·reconcile | 결제 담당자 | 백엔드·지원 | test mode 시나리오·운영 runbook·판매 gate |
| 설명·숨김·네트워크 공시 | 플러그인 담당자 | 사용자·디렉터리 심사 | README·ko/en·DOM·네트워크 회귀 검사 |

공개 배포 검증은 CI 또는 릴리스 담당자의 외부 테스트에서 수행한다. 사용자 플러그인 시작 시 웹을 호출해 검사하는 방식으로 옮기지 않는다.

- 공개 링크는 허용한 HTTPS 목적지에 도달해야 하며 언어 redirect 뒤에도 승인된 고정 query가 보존되어야 한다. 200 응답만으로 통과시키지 않는다.
- 도착 페이지의 실제 활성 플랜 카탈로그와 무료 경계가 정본 fixture와 일치해야 한다. legacy Premium·월 4.99의 활성 제안이 남아 있으면 실패다. 승인되지 않은 지원 소스·출시 상태 주장을 검사한다.
- 결제 미출시 상태에서는 테스트가 페이지의 구매 가능 문구·checkout 연결 부재를 확인한다. 판매 시작은 별도 readiness 기록과 운영 승인 뒤 test 기대값을 바꾼다.
- 플러그인의 월·연 전환 결과는 같은 fixture와 비교한다. 합계 용량·소스 수·연간 총액·가중 크레딧을 검증한다. UI 가격을 서버 SKU 선택의 근거로 신뢰하지 않는다.
- 연결되지 않은 route는 테스트 실패나 명시적인 준비 중 상태로 남겨 두고 존재하는 페이지처럼 링크하지 않는다. importer·실판매 gate를 통과하지 않았는데 출고 체크리스트를 수동 완료 처리하지 않는다.

## 15. 문서와 구현의 동기화 규칙

이 PRD의 ‘완료 기준’은 완료 보고가 아니다. 릴리스할 때 실제 코드·QA 결과·운영 상태에 따라 기능상태표와 README를 함께 갱신한다. 가격은 정본에, 기능 제공 상태는 해당 릴리스에, 실판매 가능 여부는 서버·운영 gate에 따른다. 링크가 열린 사실만으로 계정 연결·자료 이전·권한 부여가 완료됐다고 안내하지 않는다.

이 표는 첫 단계 당시 결과다. 후속 importer·웹·결제 코어 검증은 다음 절을 따른다. companion core의 통신 부재 테스트를 Obsidian 전체 프로세스의 네트워크 캡처 결과로 확대 해석하지 않는다. 기존 BYOK나 공개 공유를 실서비스로 호출하지 않았으며 새 클라우드 기능을 활성화하지 않았다.

## 17. 후속 구현과 검증 — 2026-10-23

### 수동 이전

플러그인은 설정된 습관 폴더의 registry와 날짜별 체크 파일만 읽고, 미리보기 후 `Exports/`에 새 JSON을 만든다. 허용한 필드로 다시 구성하며 보관·생성일·명시적 false를 보존한다. API 키·대화·노트 본문은 제외한다. 파일이 읽는 중 바뀌거나 계약을 위반하면 중단한다. [사용 안내와 v1 계약](obsidian-transfer.md)을 참조한다.

앱은 같은 합성 fixture를 사용하는 엄격한 v1 parser와 내용 기반 중복 방지를 구현했다. 이름으로 기존 습관과 합치지 않으며, 원본 ID와 날짜·상태를 metadata로 보존한다. 적용 전 복구 사본, 중단 복구, 사용자 편집을 덮어쓰지 않는 CAS 되돌리기를 제공한다. standalone의 여러 창도 같은 Web Lock을 사용하며 미지원 환경은 무변경 거절한다. 별도 프로세스·포트가 같은 SQLite를 공유하는 구성은 지원하지 않는다. 계정/클라우드 연결 중에는 가져오기를 거절한다.

### 웹과 결제

기존 bilingual 웹 소스를 승인된 Free/Sync/Plus·미출시 상태·공통 웹/iPhone/iPad 개발 현황에 맞췄다. 수동 이전 안내와 허용된 고정 유입 파라미터를 추가했다. 로컬 backend archive의 homepage 두 파일만 백업 후 적용했으며, manifest의 전체 23개 파일이 소스 hash와 일치한다. 공개 habitude.ai는 변경하지 않았으므로 이전 요금제 경고와 공개 배포 차단은 유지한다.

결제 서버 코어는 신뢰한 서버 인증, 고정 SKU, 영속 작업 원장 계약, 중복 checkout 방지, 응답 유실 복구, 원본 webhook/서명 adapter 경계, 최신 구독 조회, 오래된 응답의 덮어쓰기 방지를 구현했다. readiness gate는 모두 false다. 실제 공급자 SDK·sandbox·배포·사용량 예약/정산·기존 sync/AI 권한 연결은 없다. 순수 quota 판정 테스트를 실제 서비스 한도 집행으로 표현하지 않는다. 앱 저장소의 구현·검증 기록(`plans/obsidian-conversion-2026-10-23.md`)과 결제 서버 범위(`commerce/README.md`)를 따른다.

최종 exporter의 Obsidian 실앱 화면 검증은 미완료다. 합성 볼트를 reload한 뒤 앱 창이 빈 화면에 머물렀고 명령·개발 도구·정상 재시작 조작에도 반응하지 않아 저장 버튼까지 검증하지 못했다. exporter 자동 검증 및 앞선 companion 실앱 QA를 이 증거로 대체하지 않는다. 실제 iOS/Android 파일 선택도 미검증이다.

기존 Next 전체 앱 빌드는 안전한 archive에 `src/lib/env-config.ts`와 설치된 의존성이 없어 실행하지 않았다. 제외된 설정·키를 복원하지 않는다. 안전한 구성과 전체 빌드, 실제 공급자 sandbox, 영속 queue·삭제 fence·usage 집행·운영/정책 검증을 끝낸 뒤 기존 Production/실판매 개별 승인 조건을 적용한다. push·release·공개 배포·실제 청구는 이번 작업에 포함하지 않았다.


## 18. 0.5.0 공개 배포 준비

후속 직접 배포 요청으로 0.5.0 metadata·릴리스 노트를 준비했다. 새 비클라우드 합성 볼트에서 실제 Obsidian 1.13.7의 명령→미리보기→JSON 저장을 확인했다. 습관 3개·상태 13개·pluginVersion 0.5.0의 결과를 읽어 확인하고 원본 registry와 전체 로그의 bytes가 그대로임을 검사했다. 앞선 빈 창 문제를 현재 exporter 실패로 확대하지 않는다. 서비스 안내는 과거 웹 가격 불일치라는 시점 의존 문구 대신 미판매·수동 이전의 경계를 설명하도록 바꿨다.

GitHub Actions의 tag build·provenance attestation·draft release 생성이 끝난 뒤 에셋 세 개를 검증하고 발행한다. 웹과 앱은 기존 로그인·API·공유 라우트를 보존한 별도 Hosting 배포로 검증한다. 실판매 서버의 provider·권한·사용량 집행이 준비되지 않았으므로 Sync/Plus 판매는 계속 비활성이다. 이 절은 배포 준비 기록이며 실제 URL/version 검증 결과는 배포 후 별도 기록한다.
